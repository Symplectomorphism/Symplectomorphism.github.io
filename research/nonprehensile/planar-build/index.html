Planar Build

Planning nonprehensile manipulation through contact, in the plane: what is built, how it works, and what is still open.

This section describes the planar (x–z) version of the box-over-a-step problem, built in cmg on the branch master of Symplectomorphism/c-gnn. The pages are organized by topic and describe the current state; the open work is on Issues.

The problem

A disk pushes a square box over a step: the box slides on the floor, tips onto its corner against the riser, rests on the step corner, and lands on the platform. Each phase uses a different set of contacts with the environment, so a planner has to choose which contacts to make and break, in which order, and then find a motion for each change.

The approach

  1. Contact states. A state is a set of principal contacts in the sense of Xiao and Ji, recognized from a simulated pose with small tolerances.
  2. Edits. Neighboring states differ by making, breaking or shrinking one contact; several change at once only when no single change is possible.
  3. The hold gate. Before any motion is computed, a small linear program checks that the contacts which persist through an edit can hold the box, at a pose where the edit can happen. Background: deciding support derives the test from first principles. Certifying a whole box decides it for every pose in a box of poses or disk placements at once.
  4. The local solver. A realizer (Λ) tries to realize each edit that passes the gate in simulation. The dynamic realizer is the plan to replace the current one with a realizer that plans the motion with its contact dynamics and certifies what is executed.
  5. Node identity and search. A search over edits, ordered by a ranker and a value estimate, so that few expensive Λ calls are needed.

Where things stand

Part What Status
Contact states planar scene, principal contacts, recognizer Built (Xiao–Ji construction)
Edits, the hold gate validity from geometry, transfers, compound edges; the LP gate with motor limits, the transition sweep and a certified margin; makes and transfers close the added contact Built; the gate certifies holds only (Theorem B’s level)
Certifying a whole box interval certificates over boxes of poses; stick–slip plans and Theorem S; the indirect lift’s last four edits and closing transport certified over the friction band Built; certified placement in the code behind a flag (off)
The local solver the success test, the quasi-static realizer Λqs with its six default options; a stick–slip variant (off) Built; Λqs realizes every edit of the indirect lift; its plans are sequences of held poses
The dynamic realizer a certified tube per edit (B-tube) with a fixed-mode MPC tracking inside it (A-tracker); learning only as a clipped residual Planned; the architecture is adopted, nothing is built
Node identity, search node keys and merging; PHS* with outcome children and box transports; the value 𝒱₀ Built and run; given the indirect lift’s formation sequence it realizes the lift; finding the sequence unhinted is open

The current configuration: disk–box friction is a declared band μdisk ∈ [0.3, 0.5]; the gate and the tracker use 0.3; every edit is realized by Λqs with its default options; release edits and the learned skills are in the code but off (the local solver). The indirect lift’s last four edits and its closing transport are certified for every μ in the band (Certifying a whole box). From the scene alone, the planner finds the held indirect lift in 33 of 34 held-out searches with a learned V₁ and ranker π (192 calls each; admissible transition poses, δ-eroded transport targets, the box’s rotation over ±180°; Results).

Videos of the planner’s motions are on Results. Open work and known defects are on Issues.
