Search and ranking

A search over edits ordered by a ranker and a value estimate, measured in calls to the local solver.

NoteStatus

Built and run. Given the indirect lift’s formation sequence, the search realizes the lift from rest at μ = 0.3, 0.4 and 0.5 (Results). Finding that sequence from the scene alone is open and is the next work: rebuild the value 𝒱₀ for the current gate, then train a learned value V₁ by expert iteration with exploration (Issues).

The search

A node is a simulated state, identified by its formation, the disk’s connected region and the box’s pose within a 10 mm test radius, merged only when the gate’s verdicts agree (Node identity). From a node, the candidates are the edits that pass the hold gate; each expansion calls the local solver Λ, which is the expensive part. The search is policy-guided heuristic search (PHS*, Orseau and Lelis 2021): a ranker gives a probability π to each candidate edit, nodes are expanded in order of a key built from their depth, the probability of their path and a heuristic factor η from a value estimate, Λ is charged when a node is expanded, and edits the gate rejects get π = 0. For this order the number of expansions is bounded by the depth and probability of the solution, scaled by η. The theory note extends the bound to duplicate states (with the safe duplicate rule and the node key of Node identity), to a Λ that fails at random (with restarts), and to nodes popped in batches.

The search’s actions and acceptance

  • Outcome children. A call yields at most one child, labelled by the state it actually reaches. The child is accepted if it is the requested state, or if it lowers the value estimate by at least δ = 10 mm, the merge test radius of Node identity. A call that does not end in the requested formation can still leave the box where a short route continues.
  • Box transports. Besides the edits, the box can be moved within its contact state, with its own gate: a box move is refused when no disk placement on the face can push the box along the planned path (a linear program at five poses). The push to the goal aims at the goal window’s centre.
  • Releases are off. Release edits (let the box go and let it come to rest in the next state) are in the code but not part of the method: the method’s lift is held at every instant.
  • The order is PHS* with its heuristic factor η from a value function, clipped to [1, ηmax], ηmax = 10. The ranker is uniform over the legal edits for now.
  • The value. 𝒱₀: the distance to the goal in the edit graph plus the box’s distance to a fixed set of poses where the next edit passes the gate (How 𝒱₀ is built). To follow: a learned value V₁, the expected number of Λ calls to the goal, trained by expert iteration with exploration on every logged call, failures included (a call that succeeds with probability p costs about 1/p calls); the distance to the goal enters only as shaping and as an input.
  • Which ends count. An end with the disk outside its workspace (the joint ranges) is invalid; quasi-static runs reject ends reached through a dynamic event.
  • No gap screen, no retries. No distance screen filters the candidates (the gate and box transport decide; distance only orders them); the disk’s clearance check is part of the gate. The planner and every reported result use no retries. The approach to an edit lasts as long as its path needs. The settle clause of the success test is off for formation edits and required for the final goal state.

How 𝒱₀ is built

𝒱₀ is not learned and not computed during the search. It is computed once per scene and per gate, before any search, and stored as tables; at a node the search only looks values up.

The value. For a node with formation σ and box pose q = (p, θ):

𝒱₀ = w · d(σ) + min over ω in N(σ) of min( dB(q, Tω), Dcap )

  • d(σ), the graph term: the length of a shortest path from σ to a goal formation in the graph of the search’s edits (the edges of the contact-state graph W, plus the release edges when the search offers releases; a box move within σ is not an edge). An edge’s length is the expected number of Λ calls its kind of edit takes, so d is in calls.
  • N(σ): the first edits of those shortest paths.
  • Tω, the target poses: a fixed set of sampled box poses of σ at which the gate admits the edit ω with margin at least γtr = 0.1.
  • dB(q, q′) = |p − p′| + ℓ |θ − θ′|, ℓ = a/2 = 62.5 mm: the box-pose distance of Node identity, an angle counted as the arc a corner of the box travels.
  • Dcap = 0.25 m caps the pose term, and w = 2 Dcap = 0.5 m per call converts calls into metres. Because w > Dcap, one call less always outweighs any difference of pose: formations first, poses only within a formation.
  • A goal state has 𝒱₀ = 0; in a goal formation the pose term is the distance to the sampled goal poses; a formation with no route to the goal gets the largest value, w (dmax + 1) + Dcap.

The edge lengths are an input. One number per kind of edit (make, break, transfer, compound, release): 1/p̂ calls, where p̂ = (s + 1)/(n + 2) is the realizer’s success rate of that kind of edit, estimated from a table of logged calls of the realizer in the configuration the search runs (s of n logged calls accepted). A kind of edit with no logged call gets p̂ = 1/2, a length of 2 calls. If each call succeeded independently with probability p̂, 1/p̂ would be the expected number of calls until one succeeds.

Four stages.

Stage What it computes Cost on the step
Sample 1,500 configurations of each of the 328 valid formations: random poses projected onto the formation’s contacts, kept only if the recognizer reads exactly that formation, nothing penetrates and the disk is clear split across processes
Graph the formations the box can be held in (by the gate’s statics) at some sample; the edges between them; their lengths; the goal formations and goal poses of each task; d by Dijkstra; N(σ) minutes, one process
Gate Tω: each formation’s samples thinned to one per 5 mm cell (and at most 120), the search’s relaxed gate at each; one evaluation decides every edit at that pose about 17,000 gate evaluations, a few CPU-hours, split across processes
Merge one table file per scene seconds

The tables belong to the gate that computed them: when the gate changes, they must be rebuilt.

How the search uses it.

  1. Order. The heuristic factor η = clip(1 + h/g, 1, ηmax), with g = ν + 1 the calls on the path including this one and h the calls left: d(σ′) for an edit into σ′, 𝒱₀/w for a box move.
  2. Progress. A call that ends neither in its requested formation nor at the goal is kept if the box comes to rest with 𝒱₀ at least δ = 10 mm lower (a box move is also kept when it ends within δ of its target).
  3. Box-move targets. A box move within σ aims at the target poses of every edit out of σ (not only the shortest route’s next one), leaving out targets already within δ; in a goal formation it aims at the goal window’s centre. No target, no box move.

What 𝒱₀ cannot know. It knows where the gate admits an edit, not where the local solver succeeds. On the indirect lift the gate admits break(mx) from a tilt of about 20°, but the breaks that lead on to the lift leave the box at 54°–63°, and a break from about 20° ends near 50°, from where the next break fails. To 𝒱₀ these are the same edit with the same length: lengths are per kind of edit, not per pose. That is what the learned value V₁ is for: the expected number of calls to the goal from the state itself, fitted to logged calls, failures included.

The ranker

The planned architecture. The ranker in the reported runs is uniform; the attention ranker comes after the search has held solves to train on.

  • Inputs: one token per contact template (type, gap, normal, contact-set length, whether it is on), one per body, and one for the goal; attention across tokens, with learned biases for pairs that are related by containment or share a body or an environment element.
  • Output: a score per candidate edit, normalized over the candidates into π.
  • Training: supervised, from searches that call Λ without guidance on many scene instances: the policy-guided-search loss on solution paths, plus a cross-entropy on whether each Λ call succeeded.
  • Baselines: search without guidance; the gate’s margin as the score; and a learned feasibility classifier with uniform-cost search on −Σ ln P (Hauser, Bretl and Latombe, ICRA 2005).

Scene families

Family Scene and goal
F1. Step, randomized step height, box size, friction, starts; goals on the platform; also lowering the box from the platform
F2. Staircase two or three steps of random rise and tread
F3. Wall and ledge topple the box against a wall, or lift it onto a ledge beside it

One disk for now. The families come after the search finds the indirect lift on the step unhinted, and a second disk after that. Validity is computed from the geometry for each family (Contact states).

The validity tables for all three families. The builder now takes any polygonal environment and a rectangular box. It reproduces the step’s tables exactly, and built the two new families (default dimensions; random-instance ranges are documented, not yet sampled):

Step F2 staircase (2 steps) F3 wall and ledge
Certified valid formations 357 649 473
Nodes of W (recognizable, vertex–vertex only alone) 328 592 443
Excluded sets 560 pairs + 1 triple 1,624 pairs + 5 triples 840 pairs + 10 triples
Compound edges (local rule, ρ = 25 mm) 92 172 144

New in the families: concave corners the box can wedge into (80 staircase formations, 42 wall-and-ledge), and pivot-like compound edges at every convex corner. Neither has collinear edges, so the “pit” case of the theory note doesn’t arise yet.

The test: a 2 × 2 table of transfer, holding out an environment family (F3) and holding out the number of disks (once a second disk is built), with cost measured in Λ calls. A targeted literature search found learned guidance for contact or mode search tested on held-out instances, objects, object counts or robot counts, but not on a held-out family of environments; the closest work counts solver calls with learned feasibility for pick-and-place (Ortiz-Haro et al., ICRA 2023).
